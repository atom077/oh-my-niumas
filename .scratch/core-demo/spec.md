# 四页协作分析与本机只读接入

Status: ready-for-agent

## Problem Statement

开发者需要在同一真实时间轴上理解多个独立 AI 会话的执行、等待与并行关系。会话列表和累计 Token 不能说明 AI 实际活跃多久，日志缺失、压缩和 fork 又可能造成误算。

## Solution

先以合成数据提供总览、项目、会话、时间轴四页本地 Demo，再接入本机只读日志。共用分析入口保证筛选、图形与指标一致，并让缺失、推断和排除原因可见。

## User Stories

1. 作为个人开发者，我希望看到 AI 总工作量，以理解多会话执行累计。
2. 我希望同时看到活跃覆盖，以区别现实经过时间。
3. 我希望并行倍数显示公式，以知道分母是什么。
4. 我希望三个会话的条形真实重叠，以辨认并行施工。
5. 我希望按项目筛选，以关注一项工作。
6. 我希望按日期裁切，以正确统计跨日会话。
7. 我希望搜索并打开会话，以查看每轮执行。
8. 我希望同时看到会话跨度和执行累计，以避免混淆。
9. 我希望等待与执行采用不同图形，以理解两轮间隔。
10. 我希望开放等待只标状态，以免长时间离线拉高总计。
11. 我希望中止、失败、历史未闭合有明确标记，以发现数据限制。
12. 我希望 Token 重报不重复计数，以获得可信用量。
13. 我希望压缩与计数重置有说明，以避免伪精确总量。
14. 我希望无本机日志也能演示，以便复现和分享。
15. 我希望明确切换合成和本机数据，以避免把示例当作真实历史。
16. 我希望导入刷新不改源日志，以保护原始会话。
17. 我希望刷新结果幂等，以避免重复扫描增加用量。
18. 我希望浏览器和数据库只接收必要元数据，以保护对话与工具内容。
19. 我希望看见版本、作用域冲突和覆盖计数，以知道哪些记录被排除。
20. 我希望从项目下钻到会话再返回，以保留当前筛选。

## Implementation Decisions

- 用户确认三个实施切片：四页合成数据闭环；异常与日期/Token边界；本机只读导入。
- 使用 TypeScript、Node、SQLite、React、ECharts；本地服务仅绑定 loopback，不部署外网。
- 项目按会话起始 cwd 分组，后续变化保留为非内容型证据，手动映射延后。真实路径只用于服务端生成稳定匿名键，不返回浏览器。
- 主视图浅色、减少卡片与重复图表，时间轴为主视觉；四页保留日期/项目筛选。
- 日志分析与 UI 解耦；外部输入经过白名单归一化，界面只消费安全分析快照。
- 先支持经本机核实的 task_started/task_complete/turn_aborted、UserMessage item_completed、token_usage_record 与 token_count。未知格式保留诊断，不补造边界。
- 只统计闭合等待。真实 UserMessage 若只有晚于 start 的记录时间，则精确等待未知；不将记录延迟算作人工时间。
- 每轮有明确边界才提供精确执行时长；历史未闭合不标现在运行。父子/fork 作用域无法隔离时排除相关记录并说明。
- 优先独立作用域的 token_usage_record，以 response 和来源去重并交叉校验累计；token_count 用于差异提示及已验证的旧格式回退，不混加。
- SQLite 只存白名单归一化结果与扫描元数据，不存消息正文、标题、工具输出、源行全文或真实绝对路径。日志发现限于配置的数据根，不提供任意路径读取 API。
- 首次导入按文件流式读取，刷新复用未变文件；变化/截断/归档重新归一化并按逻辑 Session 合并，提供文件与事件覆盖诊断。
- Node 运行时要求支持内置 SQLite，固定在本机可用的 Node 24 LTS 系列，避免给全局 Node 14 添加依赖。

## Testing Decisions

用户已确认三个公开入口。按 TDD 一次验证一个行为，不对内部组件或私有函数写实现镜像测试。

1. 日志/Fixture → 分析结果：验证 100 min 工作量、50 min 覆盖、2.0×、裁切、Token 去重/子集/重置、异常、项目映射。捕捉算法错误；不证明桌面 UI 与日志协议一致。
2. 浏览器操作：四页、筛选、项目/会话下钻、日期与数据源切换。捕捉可见交互错误；不证明本机日志所有版本覆盖。
3. 本机导入/刷新 HTTP 接口：用隔离测试数据根验证只读、幂等、追加/截断、作用域和隐私；再对本机日志做只读冒烟。捕捉服务边界错误；不能把隔离样例成功视为全库语义证明。

## Out of Scope

Agent 控制、云上传、外部部署、人工投入采集、费用或订阅账单、完整父子 Agent 归属、手动项目映射、通用日志协议、生产安装包。

## Further Notes

依据项目背景、日志核验、指标规格与四页 UX 草案。Phase 0 的最小可行性证据已成立；桌面 UI 对照和归档真实样本仍未验证，产品必须保留这些限制。首次确认记录：2026-10-19，用户接受 Q1–Q5 推荐方案。
