# 指标口径与边界

状态：2026-10-19 实现与验收口径。指标定义以 [PROJECT.md](../oh-my-niumas-project/PROJECT.md) 第 5 节为准；日志证据见 [log-format-findings.md](log-format-findings.md)，实现验证与限制见 [verification.md](verification.md)。

## 1. 统计窗口与证据

- 内部以 UTC 时间点计算；日期窗口由明确的展示时区转换而来，不依赖宿主系统默认时区。
- 区间采用半开形式 `[start, end)`；跨午夜和筛选边界统一裁切为 `[max(start, windowStart), min(end, windowEnd))`，非正长度不计。
- 同时刻先结束旧区间、再开始新区间，避免首尾相接被算作并行。
- 每项指标携带来源引用、覆盖情况、可信度与异常列表。来源引用使用本地索引键及事件行号/偏移；对外输出不能包含真实路径、Prompt 或工具内容。
- `observed` 表示存在直接证据；`inferred` 表示有明示推断规则；`unknown` 表示无法确定。合成 Fixture 的结果必须另标 `synthetic`，不能包装成真实观测。
- 覆盖率标明分子、分母和计数对象，例如“有闭合边界的轮次 / 有开始事件的轮次”。未知分母写“未知”；抽样覆盖不等于全库覆盖。

## 2. 轮次与状态

首选以明确的轮次标识配对开始和终止事件，保留 Session、事件顺序及来源。开始、完成、中止等实际事件名由日志适配器识别，不假设所有版本都相同。

| 情形 | 表达与统计规则 |
| --- | --- |
| 明确开始 + 正常完成 | `completed`，执行区间可精确恢复 |
| 明确开始 + 明确中止 | `aborted`，截至中止的活跃区间计入，区别正常完成 |
| 明确失败终止 | `failed`；单个工具报错不是整轮失败的证据 |
| 开始无终止，只有历史静态日志 | 未闭合、`unknown`；不能仅凭末尾 start 判断现在仍在运行 |
| 开始无终止，且有实时活动证据 | 可显示 `running`，截至固定的统计快照时间；标注临时结果与最后观测时间 |
| 只有完成、没有开始 | 保留结束事件，执行时长 N/A，不用第一条消息补起点 |
| 重复或互相矛盾的边界 | 按稳定轮次标识去重；冲突单列，不静默生成多份工作量 |
| 结束早于开始 | 无效区间，报告异常，不取绝对值 |

执行中的新用户消息、审批、工具调用、助手 commentary 都不自动拆出新轮次。若日志存在重入或覆盖开始而没有明确旧轮终止，保留异常，暂不重建为精确区间。

## 3. 时间、并发与交互

设经验证、去重并按窗口裁切的 AI 区间为 `I₁ … Iₙ`，长度单位统一为毫秒。

| 指标 | 公式 / 规则 |
| --- | --- |
| AI 执行时长 | 轮次 `end - start`；工具时间已包含在内，不再相加 |
| AI 总工作量 W | `Σ length(Iᵢ)`；同一轮重复来源只计一次 |
| AI 活跃覆盖 C | `length(union(I₁ … Iₙ))`，排序后合并相交/相接区间 |
| 平均 AI 并行倍数 | `W / C`；`C = 0` 时 N/A |
| 峰值并行数 | 扫描开始/结束事件的最大活跃轮次数；同一轮不能重复入集合 |
| 会话跨度 | 窗口内活动边界的最大值减最小值；与窗口相交的执行区间边界也算活动。单一时间点为 0；无活动 N/A。实时会话若延至快照时间须注明“截至当前” |
| 闭合等待 | 完成到下一次真实用户输入；按窗口裁切，不能用下轮 start 代替输入时间 |
| 人工介入次数 | 按事件时间落入窗口的已验证用户交互分类计数；Prompt 正文不入库 |

等待总计允许不同会话间重复累计，因此可能超过现实窗口长度。中止/失败后的静默间隔暂不自动解释为等待人工。任务中途的新消息不能据此增加一段完成后的等待。

本机 S01 的 UserMessage 记录晚于对应 `task_started`，说明外层日志时间不是已验证的点击发送时间。适配器需分别保留 `inputObservedAt` 和 `aiStartedAt`。不能把两者差异归成人工耗时：若只有延迟的输入记录，真实闭合等待为 N/A；可单列“完成至输入记录间隔（含记录延迟）”或明确标为推断的轮间间隔，不能混入精确等待总计。合成 Fixture 可以显式提供真实输入时点，但该能力不代表真实日志具备。

只有部分轮次可还原时，显示“已知工作量”等限定及覆盖率；不能把缺失时长当 0 后宣称完整总量。同一会话不同轮次异常重叠时先报冲突，不默认为该会话具有多个执行槽。

### 并发验收向量（合成）

相对分钟：A `[0, 40)`，B `[10, 45)`，C `[25, 50)`。

- 工作量 `40 + 35 + 25 = 100 min`。
- 并集 `[0, 50)`，覆盖 `50 min`，平均 `2.0x`，峰值 `3`。
- 窗口 `[20, 30)`：工作量 `10 + 10 + 5 = 25 min`，覆盖 `10 min`，平均 `2.5x`。
- 相邻的 `[0, 10)` 和 `[10, 20)`：峰值 `1`。
- Asia/Shanghai 的 `23:50–次日 00:20`：前日 10 min，次日 20 min；不能每一天都计完整 30 min。

## 4. Token 记账

### 4.1 原则

1. 同一逻辑来源重复扫描必须幂等。使用文件身份、代际、偏移/行号及可验证的事件标识识别来源；不能只对 Token 数值做哈希去重，因为两次真实用量可能相等。重复复制文件/归档也不能新增同一会话同一事件的用量。
2. 区分累计、单次/最近一次与未知语义；两种字段同时存在时不相加。无法确定语义的版本保留原始数字证据，指标 N/A。
3. 对同一会话、同一计数作用域的连续累计快照 `Tₖ`，相邻差值 `Tₖ - Tₖ₋₁` 只入账一次；完全重复的累计快照贡献为 0。
4. 首个累计值只有在证据说明从该计数作用域的零点开始时，才计入完整累计。若来自中途截取或派生会话，它是基线，之前用量覆盖未知，不能当本轮新增。
5. 发生计数下降、重置、上下文压缩或来源切换，结束连续计数段，记录异常；新基线之前的缺口未知。不使用 `max(0, delta)` 悄悄吞掉重置后宣称完整。
6. Turn 级统计要求累计差值可明确归属唯一轮次，且首尾基线足够。否则仅展示 Session 级已知值，Turn 为 N/A。
7. `cached_input_tokens` 在经验证时是 input 的子集，`reasoning_output_tokens` 是 output 的子集。分项保留，但总量不重复相加；优先使用语义已验证的 `total_tokens`，并检查与 input/output 的关系。
8. 父子 Agent 的计数隔离未核实前，不把子会话加入父会话总量，也不把继承的历史累计计作子会话新增消耗。不能凭 cwd 相同去重。

### 4.2 本机已观察到的双计数路径

`token_usage_record` 含单次 `usage`、轮次累计 `turn_token_usage` 和会话累计 `thread_token_usage`。对已验证的独立作用域，优先从这一路建立账本：每个唯一来源的单次 usage 入账一次，用同作用域累计差值交叉检查；Turn 归属必须使用记录内的作用域证据，不能仅使用文件最近一次 `session_meta`。`token_count` 作为一致性与旧格式回退证据，不再另加一次。

这条规则仅适用于通过字段、作用域和数值一致性校验的日志版本；记录缺失、作用域冲突或累计对不上时标部分覆盖/未知。文件内可能含多个 session metadata，不能将整份文件的 inherited usage 无条件算给最后一个会话。

本机压缩反例：某次 `token_usage_record.usage.total_tokens = 327480`，相邻 `token_count` 累计未变，随后两条累计路径持续相差 327480。因此不能把任一路默认称为全库真实账单。账本可报告“该记录路径的已知 Token”，并保留 scope 和压缩事件；无 scope 证据时两路不做盲目互补。

该反例中 `token_count.last` 还出现 input/output 都为 0、total 却为 35160 的值。仅凭 `last` 字段名或非负数不足以认定它是可相加消耗。

### 4.3 时间归属

当前采用“可归属增量的上报事件时间”筛选 Token；完整累计用于建立基线，不能先按窗口丢弃历史再差分。跨窗一笔增量不可精确拆分时，按上报时间整笔归属并在页面注明策略；禁止按执行时长比例分摊并标成精确值。

### 4.4 必需验收向量（合成，不是本机用量）

| 场景 | 期望 |
| --- | --- |
| 已知零基线后累计 100 → 150 → 150 → 180 | 总量 180，最后一个重复 150 不贡献用量 |
| 截取日志首次看到累计 100 → 150 | 可恢复新增 50，截取前覆盖未知；不能称本轮用了 150 |
| input=100，cached=40，output=20，reasoning=5 | 验证子集后总量 120，不是 165 |
| 累计 150 → 20，无重置说明 | 计数段冲突，不能报完整 170 或静默报 150 |
| 两个不同用量事件均为增量 10 | 语义已验证时计 20；不能因数值相同去掉一个 |
| 累计与 last 字段同时重报 | 不将两者相加；last 的名称本身不足以证明可逐行求和 |
| 同一批事件刷新两次 | 第二次扫描不改变结果 |
| 压缩记录有 usage、token_count 累计不动 | 不丢压缩记录；两条计数路径不叠加，差异明确暴露 |
| 文件含两个 session_meta、usage scope 仍指向旧会话 | 保留作用域冲突，不把继承历史算作新会话新增 |
